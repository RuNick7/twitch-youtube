# Twitch → YouTube

Бот сам следит за каналом на Twitch. После конца стрима он нарезает VOD по сменам категории и названия стрима и загружает сегменты на YouTube: ролики без предупреждений публикуются сами, по остальным бот спрашивает в Telegram. Части стрима, где смотрят сериалы и фильмы, не загружаются. План проекта — в [PLAN.md](PLAN.md).

Видео не касается диска: фрагменты VOD идут с Twitch на YouTube потоком, поэтому хватает небольшого сервера с любым свободным местом.

## 1. Подготовка

### Telegram

Напишите [@BotFather](https://t.me/BotFather) команду `/newbot`, придумайте имя и сохраните токен. Свой Telegram ID искать не нужно: после первого запуска бот сам пришлёт его в ответ на `/start`.

### Google Cloud

1. Откройте [console.cloud.google.com](https://console.cloud.google.com) и создайте проект.
2. «APIs & Services» → «Library» → **YouTube Data API v3** → «Enable».
3. «Google Auth Platform» (раньше называлось «OAuth consent screen») → «Get started»: название приложения, почта, тип аудитории **External**. Логотип не загружайте: с ним Google требует проверку приложения.
4. «Data Access» → «Add or remove scopes» → добавьте `https://www.googleapis.com/auth/youtube`.
5. «Audience» → **Publish app**, чтобы статус стал «In production». В режиме «Testing» доступ к YouTube слетает через 7 дней. Проверку приложения (Verification) проходить не нужно: при входе будет предупреждение, что приложение не проверено, и это нормально.
6. «Clients» → «Create client» → тип **TVs and Limited Input devices**. Client ID и Client secret понадобятся для `.env`. Секрет Google показывает только при создании — сразу сохраните его (Download JSON).
7. **Подайте заявку на аудит** как можно раньше: [форма YouTube API](https://support.google.com/youtube/contact/yt_api_form). Пока аудит не пройден, YouTube навсегда блокирует загруженные через API ролики как приватные: открыть их нельзя даже вручную, только загрузить заново. Бот в это время работает, но вместо публикации присылает 🔒. Для заявки нужны сайт, политика конфиденциальности и условия использования. У этого бота они на [GitHub Pages](https://runick7.github.io/twitch-youtube/), в ветке `gh-pages`. Для своей копии бота опубликуйте свои страницы и укажите их в `PRIVACY_URL` и `TERMS_URL`.

Ключи Twitch API не нужны: бот следит за каналом через yt-dlp.

### YouTube

Подтвердите канал по телефону на [youtube.com/verify](https://www.youtube.com/verify), иначе ролики длиннее 15 минут не загрузятся.

### Стример

- Письменное разрешение на нарезки.
- Архив трансляций включён и доступен всем, а не только подписчикам.
- Если у стримера свой YouTube с Content ID — ваш канал в его списке исключений.

## 2. Установка на сервер

Docker, если ещё не установлен:

```bash
curl -fsSL https://get.docker.com | sh
```

Swap на 2 ГБ, если `swapon --show` ничего не выводит:

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile && echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

Скачайте проект с GitHub (если git не установлен: `apt install -y git`). Сервер входит по ключу развёртывания (deploy key) с правом только на чтение — так клонирование работает, даже если репозиторий снова станет приватным. Если ключа ещё нет, создайте его на сервере и добавьте выведенную строку в настройках репозитория: Settings → Deploy keys → Add deploy key.

```bash
ssh-keygen -t ed25519 -f ~/.ssh/twitch_youtube -N "" && cat ~/.ssh/twitch_youtube.pub
```

Клонирование. Ключ запоминается в настройках копии, поэтому потом `git pull` работает без лишних параметров:

```bash
git clone -c core.sshCommand="ssh -i ~/.ssh/twitch_youtube -o IdentitiesOnly=yes -o StrictHostKeyChecking=accept-new" git@github.com:RuNick7/twitch-youtube.git /opt/twitch-youtube
```

На сервере создайте `.env` из шаблона и заполните его. Там же описаны необязательные настройки: время до публикации, слова и категории фильтра, ограничение скорости.

```bash
cd /opt/twitch-youtube && cp .env.example .env && nano .env
```

Ключ для `SECRET_KEY`:

```bash
python3 -c "import base64,os; print(base64.urlsafe_b64encode(os.urandom(32)).decode())"
```

Запуск:

```bash
docker compose up -d --build
```

Дальше:

1. Напишите боту `/start`. Он пришлёт ваш ID. Впишите его в `TELEGRAM_OWNER_ID` и перезапустите контейнер: `docker compose up -d`.
2. Отправьте `/youtube`. Бот покажет, что он будет делать с каналом, и попросит принять политику конфиденциальности — нажмите «Принимаю». Откройте ссылку, введите код и войдите в аккаунт канала. На предупреждении «Google hasn't verified this app» нажмите «Advanced» → «Go to … (unsafe)», выберите канал и разрешите доступ.
3. Готово: после следующего стрима бот всё сделает сам. Эфиры, закончившиеся до первого запуска, можно отдать вручную: `/process https://www.twitch.tv/videos/…`.

## 3. Как это работает

Раз в 5 минут бот проверяет канал, а пока идёт стрим, раз в минуту запоминает его название. Через 10 минут после конца стрима он режет VOD по сменам категории и названия:

- куски с той же категорией и тем же названием склеиваются в один ролик — например, Just Chatting в начале и в конце стрима;
- кусок короче 2 минут (случайное переключение, исправленная опечатка) приклеивается к соседнему, а ролик короче 7 минут не загружается;
- Just Chatting, в названии которого упомянут сериал или фильм, не загружается.

Название ролика: «Категория | Название стрима | Часть N | Заквиель».
- Номер части сквозной по категории, от стрима к стриму: первый ролик игры — «Часть 1», следующий, даже через неделю, — «Часть 2». Названия уже вышедших роликов не меняются.
- Пропущенные куски номер не получают. Кусок, загруженный кнопкой «Всё равно загрузить», получает следующий свободный номер.
- У Just Chatting и Minecraft (`NO_PART_CATEGORIES`) номера нет.
- Имя в конце задаётся в `STREAMER_NAME`: так стримера ищут зрители.
- Если название не помещается в 100 символов, сокращается название стрима.

Опубликованный ролик попадает в плейлист своей категории, например «Minecraft | Заквиель». Плейлист создаётся вместе с первым роликом категории, ролики идут в порядке публикации. Если удалить плейлист на YouTube, бот создаст новый со следующим роликом. Выключить плейлисты: `PLAYLISTS=false`.

Под пропущенным сегментом есть кнопка «Всё равно загрузить».

Остальные сегменты по одному загружаются на YouTube приватно. Когда YouTube обработал ролик, бот ждёт ещё час, пока отработает Content ID, и проверяет:

- не отклонён ли ролик и не заблокирован ли он целиком или в части стран;
- нет ли ограничения 18+;
- совпадает ли длительность;
- не из рискованной ли категории сегмент.

Предупреждений нет — ролик публикуется. Есть — приходит вопрос с кнопками «Опубликовать» и «Оставить приватным». Опубликованные ролики бот проверяет ещё 3 дня и сообщит, если YouTube их заблокирует.

Претензии Content ID вида «доход уходит правообладателю» через API не видны, поэтому фильтр сериалов и фильмов важен: если на стримах появятся новые сериалы, добавьте их в `SKIP_TITLE_KEYWORDS`.

Сообщения о ходе работы приходят без звука. Со звуком — только вопросы и проблемы: ⚠️, 🔴 и 🔒.

Раз в сутки бот сверяется с YouTube, как требуют правила YouTube API. Он проверяет, что доступ к каналу ещё действует, обновляет название канала и доступ роликов, забывает удалённые плейлисты, а данные о роликах, удалённых с YouTube, стирает (🗑). Если доступ отозван в настройках Google-аккаунта, бот удаляет токен, данные канала и ID роликов и сообщает об этом. `/disconnect` делает то же самое сразу и вдобавок отзывает доступ в Google. Сами ролики на YouTube в обоих случаях остаются.

## 4. Команды бота

| Команда | Что делает |
|---|---|
| `/process <ссылка на VOD>` | обработать VOD вручную (старый или пропущенный) |
| `/youtube` | подключить или переподключить YouTube-канал |
| `/disconnect` | отключить YouTube-канал: отозвать доступ в Google и удалить сохранённые данные о канале и роликах |
| `/status` | стрим сейчас, подключения, сегменты по статусам, свободное место, версия yt-dlp |
| `/pause`, `/resume` | остановить и продолжить загрузку и автопубликацию |

Кнопки под сообщением сегмента:

| Кнопка | Когда |
|---|---|
| ⬆️ Всё равно загрузить | сегмент пропущен фильтром сериалов (тогда публикация только по решению) или он короче 7 минут |
| 🚀 Опубликовать сейчас, 🔒 Не публиковать | ролик ждёт проверки Content ID |
| ✅ Опубликовать, 🔒 Оставить приватным | у ролика есть предупреждения |
| ✅ Всё-таки опубликовать | ролик оставлен приватным |
| 🔁 Повторить | загрузка не удалась |

Если проблема не в самом сегменте (слетел доступ к YouTube, дневной лимит загрузок), обработка встаёт на паузу до `/resume`.

## Обслуживание

- Логи: `docker compose logs -f app`
- Обновление кода: `cd /opt/twitch-youtube && git pull && docker compose up -d --build`.
- yt-dlp обновляется сам при каждом старте контейнера и раз в сутки.
- Данные лежат в `./data/app.db`. Видео на диск не пишется.

## Тесты

Юнит-тесты не требуют зависимостей:

```bash
python3 -m unittest discover -s tests -t .
```

Сквозной тест `tests/e2e_flow.py` запускает приложение целиком с поддельными Telegram и YouTube, а видео берёт с настоящего Twitch: фильтр, нарезка по названию, склейка повторов, потоковая загрузка со сбоями и перезапуском, автопубликация, решения кнопками, слежение за каналом, ежедневная сверка, отключение канала и отзыв доступа. Идёт около двух минут и требует интернета. ID VOD в начале файла со временем устаревают — Twitch удаляет записи через 60 дней.

```bash
docker build --target test -t twitch-youtube-test . && rm -rf /tmp/e2e && mkdir /tmp/e2e && docker run --rm --init --cpus 0.6 --memory 768m -v "$PWD/app:/srv/app:ro" -v "$PWD/tests/e2e_flow.py:/srv/e2e_flow.py:ro" -v /tmp/e2e:/work twitch-youtube-test python e2e_flow.py
```
