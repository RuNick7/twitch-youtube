# Twitch → YouTube: план v3

Цель: после окончания стрима автоматически нарезать VOD по сменам категории, отправить сегменты на подтверждение в Telegram и загрузить одобренные на YouTube, соблюдая правила YouTube. Всё работает в Docker на одном небольшом Ubuntu-сервере.

## Исходные данные

- Один стример, который официально разрешил делать нарезки; один YouTube-канал на стримера. Позже стримеров может стать больше.
- Проверяет один человек, одобрение — в Telegram. Сайт пока не нужен.
- Сообщение «эфир начался» не нужно, тихих часов нет.
- Особых правил нарезки нет: каждая смена категории — отдельное видео, главный ориентир — правила YouTube.
- Сервер: 1 vCPU 3,3–4,6 ГГц, 2 ГБ DDR5 ECC (процессор и память уже заняты на 30%), канал 500 Мбит/с. Бот работает на нём же.

## Что изменилось по сравнению с v2

Все изменения продиктованы сервером: одно ядро и 2 ГБ памяти не потянут перекодирование и лишние сервисы.

- Сайт, Mini App, домен, Caddy, Postgres и EventSub отложены. Остаётся один контейнер, наружу не открыт ни один порт: к Telegram, Twitch и YouTube ходим только исходящими запросами.
- Twitch отслеживаем опросом API раз в минуту. Для одного стримера это проще и надёжнее EventSub, а точные границы всё равно берутся из глав VOD. От Twitch нужны только client_id и secret приложения, входить в аккаунт не придётся.
- Весь VOD больше не качаем: сначала проверка, потом скачивание только одобренных кусков. Экономит диск, трафик и время.
- Превью для проверки (раскадровка, клипы границ) берутся из лёгкой версии VOD без перекодирования.
- YouTube-канал подключается кодом через бота (google.com/device), без сайта и redirect-адреса.
- База — SQLite вместо Postgres.
- Добавлен раздел «Правила YouTube».

## Хватит ли сервера

| Ресурс | Что нужно | Вывод |
|---|---|---|
| CPU | видео не перекодируем; кадры и клипы берём из лёгкой версии VOD | хватит; контейнеру даём до 60% ядра, подпроцессы под `nice`/`ionice` |
| Память | пик нашей части ~300–450 МБ из ~1,4 ГБ свободных | хватит; swap 2 ГБ на всякий случай, лимит контейнера 768 МБ |
| Канал 500 Мбит/с | трёхчасовой сегмент 1080p60 весит 8–11 ГБ; при ограничении 200–250 Мбит/с он качается и загружается за 5–10 минут в каждую сторону | с запасом; скорость ограничиваем, чтобы не мешать остальному на сервере |
| Диск | на диске только сегмент, который сейчас в работе; худший случай — восьмичасовой стрим одной игрой, 22–29 ГБ | нужно ~40 ГБ, свободно 57 ГБ из 79 — хватает |

Чего на этом сервере не будет: перекодирования целых видео, облегчённых копий для просмотра, рендера чата поверх видео.

## Конвейер

```
Раз в минуту GET /helix/streams: идёт ли стрим и какая категория
      ▼ стрим закончился, 10 минут тишины (вдруг переподключение)
VOD по stream_id + главы (yt-dlp -J, само видео не качаем)
      ▼
Сегменты: каждая смена категории — отдельное видео
(короче 2 мин — приклеиваем к соседнему, длиннее 12 ч — делим на части)
      ▼
Telegram: карточка стрима + сообщение на каждый сегмент
(раскадровка и клипы границ — из лёгкой версии VOD, без перекодирования)
      ▼ «Одобрить»
Скачиваем только этот кусок в исходном качестве, сверяем длительность
      ▼
YouTube: загрузка приватно с публикацией по расписанию
      ▼
Файл удаляем сразу после загрузки; до публикации бот следит за статусом видео
```

Если диск окажется большим (от 100 ГБ), можно включить режим «качать сразу»: все сегменты скачиваются сразу после стрима, и тогда VOD, удалённый до проверки, не страшен.

Главы без скачивания видео:

```bash
yt-dlp -J https://www.twitch.tv/videos/VOD_ID
```

Скачать только нужный кусок (что быстрее на этом сервере — yt-dlp или TwitchDownloaderCLI с `--beginning`/`--ending` — замерим на этапе 1):

```bash
yt-dlp --download-sections "*01:23:45-03:10:00" -o "/data/work/%(id)s_part.%(ext)s" https://www.twitch.tv/videos/VOD_ID
```

Кадры для раскадровки ffmpeg берёт прямо из HLS-плейлиста лёгкой версии VOD с `-ss` перед `-i`: скачивается только нужный фрагмент в несколько мегабайт. Клипы границ — оттуда же с `-c copy`. Если у канала нет лёгких версий, берём исходник: 30 секунд — это 25–35 МБ, в лимит Telegram укладывается.

## Проверка в Telegram

Карточка стрима появляется, когда стрим закончился, и обновляется по ходу работы:

```
📺 Стрим 29.09 «Строим замок» · 6 ч 12 мин · 4 сегмента
⏳ На проверке 3 · ⬆️ Загружено 1
```

Сообщение на сегмент:

```
[раскадровка: 9 кадров одной картинкой]
🎮 Minecraft · 01:23:45–03:10:00 (1 ч 46 мин)
Название: Minecraft — Строим замок | Стример
Публикация: сегодня 18:00

[✅ Одобрить] [❌ Отклонить]
[✏️ Название] [✂️ Границы] [🕒 Время]
[💰 Реклама: нет] [▶️ Смотреть на Twitch]
```

- «Смотреть на Twitch» открывает VOD на Twitch с начала сегмента — просмотр без нагрузки на сервер.
- «Границы» открывает меню: начало и конец ±30 секунд, ввод точного времени, клипы вокруг границ (по 15 секунд до и после), «Склеить со следующим».
- «Название»: бот просит ответить новым текстом и проверяет лимиты YouTube.
- «Время»: «как только YouTube проверит», «сегодня 18:00», «завтра 18:00» или своё.
- «Реклама» — переключатель для сегментов со спонсорской интеграцией (см. «Правила YouTube»).
- «Отклонить» переспрашивает «Точно?». После решения кнопки исчезают, на сообщении остаётся итог.

После загрузки:

```
✅ Загружено: youtu.be/… (приватно)
Публикация сегодня в 18:00, если YouTube не найдёт нарушений
[🚀 Опубликовать сейчас] [⏸ Отменить публикацию]
```

Команды:

- `/process <ссылка на VOD>` — обработать любой VOD вручную (старый или пропущенный);
- `/status` — очередь, диск, подключения;
- `/pause`, `/resume` — остановить и запустить обработку;
- `/log` — последние 20 событий;
- `/youtube` — подключить или переподключить YouTube-канал кодом.

## Предупреждения

🔴 — нужно действие, 🟡 — обработка идёт дальше. Когда проблема уходит, бот отвечает на предупреждение «✅ Решено». Одно и то же предупреждение приходит не чаще раза в час.

| Событие | Уровень | Кнопки |
|---|---|---|
| Скачивание не удалось или файл битый (длительность не совпала с ожидаемой) | 🔴 | Повторить |
| VOD исчез или стал недоступен до скачивания | 🔴 | Пропустить |
| Загрузка на YouTube не удалась или упёрлась в дневной лимит канала | 🔴 | Повторить, Отложить |
| YouTube отклонил видео (`rejectionReason`: claim, copyright, duplicate…), публикация отменена | 🔴 | Открыть в Studio |
| После времени публикации видео осталось приватным — скорее всего, аудит API ещё не пройден | 🔴 | — |
| Доступ к YouTube отозван или истёк | 🔴 | Переподключить |
| Свободного места меньше, чем нужно для следующего сегмента, обработка на паузе | 🔴 | Продолжить |
| VOD удалится через 2 дня, а сегменты ещё не проверены | 🟡 | Открыть |
| Короткий сегмент приклеен к соседнему или длинный разделён | 🟡 | Отменить |
| В VOD есть заглушённые фрагменты | 🟡 | — |
| Сегмент из рискованной категории (казино, ставки) | 🟡 | — |
| Перезапуск после сбоя, обработка продолжена | 🟡 | Журнал |

Срок жизни VOD бот считает сам: тип канала (партнёр, компаньон или обычный) отдаёт `GET /helix/users`.

Если упадёт сам сервер, бот об этом не скажет. Для этого на этапе 4 подключим внешний «пульс»: приложение раз в 5 минут отмечается в сервисе вроде Healthchecks.io, и если отметки прекратились, оттуда придёт сообщение в Telegram.

## Правила YouTube

Что делаем автоматически:

1. Аудитория: у каждого видео явно `selfDeclaredMadeForKids=false`. YouTube требует указывать аудиторию для каждого ролика.
2. Спонсорские интеграции: кнопка «Реклама» ставит `paidProductPlacementDetails.hasPaidProductPlacement=true`. Платную рекламу в ролике YouTube требует раскрывать.
3. Метаданные без спама: название до 100 символов, описание до 5000 байт, теги в сумме до 500 символов, без `<` и `>`, без кликбейта. Шаблон названия: «{игра} — {название стрима} | {стример}».
4. Указание автора: в описании ссылка на Twitch стримера и строка «Опубликовано с разрешения автора».
5. Авторские права: загрузка приватная с отложенной публикацией; бот проверяет статус через `videos.list` и, если YouTube отклонил ролик, отменяет публикацию. Частичные претензии Content ID (доход уходит правообладателю) через API не видны — только в YouTube Studio. Заглушённые на Twitch фрагменты уменьшают число таких претензий.
6. Казино и ставки: сегменты из категорий вроде Slots и Virtual Casino помечаются 🟡. С 19 марта 2025 года YouTube запрещает ссылки, логотипы и упоминания непроверенных гемблинг-сайтов, а контент с онлайн-казино получает возрастное ограничение. С 17 ноября 2025 года то же касается сайтов со ставками на скины и другие цифровые предметы.

Что нужно сделать вам:

- сохранить письменное разрешение стримера — пригодится при спорах и для заявки на аудит;
- если у стримера есть свой YouTube с Content ID, попросить добавить ваш канал в список исключений (allowlist), иначе его система будет заявлять права на ваши ролики;
- если нужна монетизация: даже с разрешением автора YouTube может отказать в партнёрской программе из-за «повторно используемого контента». Нужен заметный собственный вклад (монтаж, хайлайты, комментарии), а не просто перезалив стрима.

## Архитектура

```
app — один контейнер (Python 3.12, restart: unless-stopped)
├─ bot       aiogram 3, long polling — весь интерфейс
├─ watcher   раз в минуту GET /helix/streams (app access token)
├─ pipeline  очередь задач в SQLite; yt-dlp и ffmpeg — подпроцессы
├─ youtube   resumable upload частями по 32 МБ; вход по коду с google.com/device
└─ health    диск, токены, статусы видео на YouTube, сроки жизни VOD
/data: app.db (SQLite), work/ (временные файлы)
```

- Наружу ничего не открыто: все соединения исходящие, домен и HTTPS-сертификат не нужны.
- SQLite вместо Postgres экономит около 100 МБ памяти и целый контейнер. Доступ к базе через SQLAlchemy и миграции Alembic, поэтому переезд на Postgres при росте — вопрос настройки.
- Задачи выполняются по одной: одно скачивание, одна загрузка. Каждый шаг записывает прогресс в базу и после перезапуска продолжается с места остановки (загрузка на YouTube — с последнего принятого куска).
- Таблица `streamers` (Twitch-канал ↔ YouTube-канал, шаблоны) есть с первого дня: второй стример — это новая строка и команда `/youtube`.
- yt-dlp обновляется при старте контейнера и раз в сутки: Twitch периодически ломает скачивание.
- После скачивания длительность файла сверяется через `ffprobe` с ожидаемой. Причина — открытый баг yt-dlp #15825: у длинных VOD Twitch конец видео может «сжиматься» в несколько секунд. При расхождении повторяем через TwitchDownloaderCLI.
- Refresh-токен YouTube лежит в базе в зашифрованном виде, ключ шифрования и токен бота — в `.env`. Бот отвечает только вашему Telegram user_id.
- Логи Docker с ротацией (`max-size: 10m`), чтобы не забить диск. Бэкап базы раз в сутки.

## Справка по API

### Twitch (Helix, app access token)

| Задача | Метод |
|---|---|
| Идёт ли стрим, категория, время начала | `GET /helix/streams?user_id=…` |
| VOD стрима | `GET /helix/videos?user_id=…&type=archive` → `stream_id`, `duration`, `muted_segments` |
| Тип канала (для срока жизни VOD) | `GET /helix/users` → `broadcaster_type` |
| Главы и скачивание | официально нет → yt-dlp (внутренний GraphQL Twitch), запасной — TwitchDownloaderCLI |

VOD хранятся 7 дней у обычных каналов, 14 у компаньонов, 60 у партнёров и владельцев Turbo/Prime.

### YouTube Data API v3

| Задача | Метод | Стоимость и лимиты |
|---|---|---|
| Загрузка | `videos.insert` (resumable) | 1 unit в отдельном лимите, 100 загрузок в сутки на проект; файл до 256 ГБ и 12 часов |
| Обложка | `thumbnails.set` | 50 units; файл до 50 МБ; нужен подтверждённый канал |
| Плейлист | `playlistItems.insert` | 50 units из общих 10 000 в сутки |
| Опубликовать сейчас или отменить публикацию | `videos.update` | 50 units |
| Статус после загрузки | `videos.list` (`status.uploadStatus`, `status.rejectionReason`, `status.privacyStatus`, `processingDetails`) | 1 unit |
| Отложенная публикация | `privacyStatus=private` + `publishAt` | — |
| Без уведомлений подписчикам | `notifySubscribers=false` | — |

Авторизация — device flow: OAuth-клиент типа «TVs and Limited Input devices», бот присылает код, вы вводите его на google.com/device (код действует 30 минут). Для этого способа доступен scope `youtube` (`youtube.upload` — нет), он покрывает загрузку и изменение видео. Refresh-токен выдаётся всегда.

### Telegram Bot API (сейчас 10.3)

- кнопки под сообщением, с 9.4 — цветные (`style`);
- редактирование отправленных сообщений (карточка стрима, итог решения);
- `answerCallbackQuery` — всплывающий ответ на нажатие;
- `ForceReply` — ввод названия и времени ответом на сообщение;
- long polling (`getUpdates`) — входящий порт не нужен.

## Ограничения и как их обойти

| Ограничение | Как обойти |
|---|---|
| Нет официального API для скачивания VOD | yt-dlp; обновляем ежедневно, запасной TwitchDownloaderCLI, 🔴 при ошибке |
| Главы есть только во внутреннем API | yt-dlp + категория из опроса `/streams` как запасной источник + ручная правка границ |
| VOD может исчезнуть до проверки | предупреждение о сроке жизни; режим «качать сразу» при большом диске; попросить стримера не удалять VOD и не делать их только для подписчиков |
| Видео из непроверенного API-проекта блокируются как приватные | заявка на аудит в первый день. Пока идёт аудит, ролики загружаются приватно и блокируются; после одобрения бот перезальёт их, заново скачав сегменты с Twitch, пока VOD ещё хранятся. Срочный ролик — забрать файл с сервера по SFTP и загрузить вручную через Studio |
| Refresh-токен Google живёт 7 дней в режиме Testing | consent screen в «In production»; один раз пройти экран «приложение не проверено» |
| Без подтверждения канала — максимум 15 минут | подтвердить по телефону на youtube.com/verify: до 12 часов и 256 ГБ |
| Скрытый суточный лимит загрузок на канал | очередь, повтор с паузой при `uploadLimitExceeded` |
| 100 загрузок в сутки на проект | хватает с запасом, в том числе на нескольких стримеров. Несколько проектов ради обхода квоты заводить нельзя — это нарушение ToS |
| Бот отправляет файлы до 50 МБ | видео не шлём: раскадровка, короткие клипы, ссылка на Twitch |
| Лимиты Telegram (~1 сообщение в секунду в чат) | очередь отправки, одна карточка на стрим |
| Telegram в России заблокирован примерно на 95% (с апреля 2026) | с сервера Telegram доступен, прокси не нужен; если это изменится — бота можно пустить через прокси (aiogram это умеет) |

## Этапы

**Этап 0 — подготовка**

- сервер: swap 2 ГБ, Docker (место и доступ уже проверены);
- стример: письменное разрешение; архив трансляций включён и доступен всем; если есть свой YouTube с Content ID — добавить ваш канал в исключения;
- Twitch: приложение на dev.twitch.tv (нужна включённая 2FA) → client_id и secret;
- Google Cloud: проект, YouTube Data API v3, OAuth consent screen (External → In production), OAuth-клиент «TVs and Limited Input devices»;
- заявка на аудит YouTube API: понадобится публичная политика конфиденциальности, её можно разместить на GitHub Pages;
- YouTube-канал: подтвердить по телефону;
- Telegram: бот в @BotFather → токен; ваш user_id.

**Этап 1 — минимальная версия (код готов, установка описана в README.md).** Контейнер app, команды `/youtube` и `/process`: главы → сегменты → сообщения с кнопками «Одобрить» и «Отклонить» → скачивание куска → загрузка приватно → ссылка. 🔴 при ошибках. Замер скорости скачивания кусков: yt-dlp против TwitchDownloaderCLI.

**Этап 2 — автоматизация.** Отслеживание стримов, запуск через 10 минут после конца, карточка стрима, `/status`, `/pause`, `/resume`, `/log`, предупреждения.

**Этап 3 — удобная проверка.** Раскадровка, клипы и сдвиг границ, склейка, название, время публикации, кнопка «Реклама», «Опубликовать сейчас» и «Отменить публикацию», контроль статуса видео на YouTube, правила YouTube из раздела выше.

**Этап 4 — надёжность.** Проверка длительности и запасной скачиватель, продолжение загрузки после перезапуска, предупреждения о сроке жизни VOD, внешний пульс, бэкап базы.

**Этап 5 — когда понадобится.** Второй стример (в архитектуре уже заложен), сайт или Mini App (нужны домен и Caddy), Postgres и EventSub при большом числе стримеров, запись эфира через streamlink (если стример выключит архив), рендер чата и облегчённые копии — только на сервере помощнее.
